# Language study app: guide for coding agents

A personal language-learning website. You save sentences you meet (from YouTube videos, books and so on), then study them. You can listen to them on repeat, see the nouns coloured by gender, and answer GPT-made practice questions at your CEFR level.

## The owner and how to work with them

- The owner is a **beginner programmer**. Explain changes in plain words, keep the code simple, and give step-by-step instructions when they need to do something themselves.
- They test on a Mac browser **and an iPhone**. Everything must work on touch screens (`canHover` in app.js switches hover menus to tap).
- **Every change gets a checkbox line appended** to [notes/plan20261024.md](notes/plan20261024.md) (`- [x] …`). Keep doing this.
- The code comments are written for a beginner: friendly, short, and explaining *why*. Match that style and comment density.
- After finishing, tell them which files changed so they can upload those.
- Design preferences they've stated: no background pictures (colours only), calm and eye-friendly, readable contrast, and **identical layout in every theme** (themes may only change colours and fonts, never sizes or positions).

## Hard constraints

- **Static site, no server, no build step, no npm.** Plain HTML, CSS and JS. Hosted on **GitHub Pages**, where the owner uploads files by hand through the GitHub website. The folder is not a git repo.
- **Never read, print or copy `key.txt`.** It holds the owner's OpenAI API key. The key must never appear in any website file. Users paste it into ⚙️ Settings → OpenAI, which stores it in `localStorage` only. `.gitignore` lists `key.txt`.
- Opening `index.html` as `file://` mostly works, but YouTube embeds fail there (error 153). Hosted on GitHub Pages it's fine.
- Fonts come from Google Fonts and must cover **latin-ext** (Polish ą ę ł ś ż, Turkish ğ ı ş, German ß, French accents).

## Features (UI tour)

- **Header:** the centred title shows the chosen language. The language dropdown (`#language-dropdown`) that sets `myLanguage` is the first thing in the Study tab (`#study-tab > .dropdown`, on its own row, centred with `width: fit-content; margin: 0 auto`, its list centred under it); the sentence forms have their own copy of the button (see Sentences tab).
- **Study tab**
  - *Select entry:* the sentences in the current language, grouped by audio file (`showEntries`: a list of groups, newest audio first, plus "📝 Without audio"; `openEntryGroup` = opened group, saved in `view`). Inside a group, `showGroupEntries` lists entries numbered in audio order with their part ("#2 · 1:05:500 – 1:20:250", via `timeLabel`), two-line previews, and the selected one in full. With no audio at all, entries are listed directly. Clicking one sets `selectedEntry`.
  - *Practice* subtab:
    - CEFR level picker (A1–C2, coloured per theme);
    - Practice Target (noun/verb/adjective/mix; `targetWords` turns it into prompt wording);
    - **✨ Spin Up a Challenge**, which asks GPT for questions about the selected entry.
  - *Immerse* subtab:
    - **Pure Text**: the sentence, big.
    - **Grammar Lens**: GPT finds the nouns, which are coloured by gender (`NOUN_GENDERS`; English and Turkish have none).
    - **Word Focus**: GPT splits the entry into learning units, single words and 2–4 word chunks, covering every word in order (word, base, type incl. phrase/collocation/phrasal verb/idiom, form or usage note, meaning; `wordsCoverText` checks coverage and asks once more). Lists without `format: WORD_LIST_FORMAT` are regenerated when opened. Shown as cards (`findWords` → `drawWordList`, `showWordFocus`). Saved on the sentence as `words: { text, list, format }`, like `grammar: { text, nouns }`, so each entry is asked about only once. No filtering of words seen in other entries (owner's choice). Tapping a card marks the word as known (`toggleKnown`); known words are stored per entry id in localStorage `knownByEntry` by lower-case dictionary form, shown only as small "✓ Known" chips under that entry's cards (tap to undo; no overview page, by request), and all of the language's known words (`allKnownWords`) are sent to `askForQuestions` (300 at most) so questions practise other words and glossaries skip them.
    - **Audio controls**: play, plus repeat 5 / 10 / infinite. The audio plays the attached MP3 part if there is one, otherwise browser text-to-speech.
- **Sentences tab**
  - The add form: a textarea (one sentence per line), a language button, Source, and an audio picker. The Add and Edit forms use `makeLanguagePicker(select)`: the same button and list as Study (`.language-button`, styled with `:is(#language-button, .language-button)`; `setUpDropdown` handles opening, keyboard and ARIA, `fillLanguageItems` the ticked languages), which only changes that form's hidden `<select>` (`#sentence-language` in Add), because `makeAudioPicker` and `addSourceSuggestions` read it and its `change` event. Add starts at `myLanguage` and goes back to it after adding or when Study's language changes (`resetAddFormLanguage`). Edit starts at the entry's language, shown even if no longer ticked. The audio picker lets you choose or upload an MP3 and mark the start/end times.
  - The list: a filter by language, and rows with three columns:
    - left: flag and topic tags;
    - middle: the text and a source link;
    - right: the date and the Edit/Delete buttons, where Delete asks "Delete it?" with Yes/No.
    - Phones (≤600px): the same row is stacked with CSS grid (flag+topics | date, then the text full width, then the buttons); `.sentence-actions` becomes `display: contents`. These phone rules must stay **after** the normal `.sentence-*` rules in style.css.
    - Long sentences are clamped to 3 lines with a "Show all ▾" toggle (`expandedSentences`, `showTextToggles`, re-measured on tab switch and resize). Audio file names are clamped to 2 lines.
  - Pasting is tidied (`tidyText(text, oneLine)` via `tidyWhenPasted`): no empty lines, trimmed lines, single spaces. The Add box keeps one sentence per line; the Edit box joins lines with a space. Add and Save tidy the text too.
  - The Source boxes (Add and Edit) suggest earlier non-link sources in the form's language (`addSourceSuggestions`, a `<datalist>` refilled on focus and language change).
  - Topics are detected automatically and are not edited in the UI.
- **Settings tab:** Theme buttons (`#theme-options` is a grid, `repeat(4, 1fr)`, 2 columns ≤760px; each `.theme-card` has the fixed `--theme-card-height` 50px, `--theme-button-padding` 0 12px, centred one-line name; all names are 17px with `font-size-adjust: 0.48` (same lowercase height in every font), weight 400 via `--theme-name-weight` (Peach Rosewater 500), card padding 0 6px, two columns ≤840px so "Honey Coconut Hour" fits; scaled by `--theme-name-scale` 0.86 ≤600px; re-measure them when a theme's heading font changes; the selected ring is a box-shadow, never a thicker border), My languages (checkboxes), Topics (status, re-check all, try a sentence), OpenAI key and model, and **Backup** (⬇️ Download / ⬆️ Restore: one JSON file with the `BACKUP_KEYS` localStorage values plus every MP3 as a data URL; the OpenAI key is deliberately left out; restore shows a "Restore this backup?" box with Replace with backup / Cancel, stores the new audio before removing old, then reloads). **When adding a new saved key, add it to `BACKUP_KEYS`** (except `theme`, which stays with the device: restoring never changes it).
- **Audio tab** (`#audios-tab`): the uploaded audio files, laid out like sentence rows (flag | name, source, sentence count | date, Edit/Delete), with the same language filter (`makeLanguageFilter` is shared by both lists). Both lists show newest first via `newestFirst(items, all)`, which only changes the on-screen order; rows still use their index in the saved array. Source is required when editing.

## Data (all in the browser, per device)

Use the helpers `loadSaved(key, fallback)`, `loadSavedText(key)` and `save(key, value, quiet)`. `save` without `quiet` shows the "Saved ✓" toast, and passing `null` removes the key.

| localStorage key | Contents |
|---|---|
| `sentences` | `[{ id, text, language, topics[], ownTopics[], source, date: "YYYY-MM-DD", audioId?, audioStart?, audioEnd? }]`. Old formats are migrated on load (see the comment above `let sentences`). Dates are shown European-style via `europeanDate`. |
| `audioLibrary` | `[{ id, name, language, source, date }]` (date = day uploaded; older files get the date of their first sentence). The MP3 data itself lives in **IndexedDB** db `language-app`, store `audio`, keyed by id (`storeAudioFile` / `loadAudioFile` / `removeAudioFile`). One file can serve many sentences. |
| `myLanguage`, `myLanguages` | The current language, and the languages ticked in Settings. |
| `myLevel`, `practiceTarget`, `audioLoops`, `audioSpeed`, `theme` | Settings that are remembered. |
| `knownByEntry` | Words marked known in Word Focus, per entry: `{ "entry-...": ["dzisiaj"] }`. `knownWithoutEntry` = `{ Polish: [...] }`, older words in no entry's list (never shown, only avoided by questions). Old `knownWords` (per language) is moved over on load, also after restoring an older backup. |
| `openaiKey`, `openaiModel` | The user's key, and the model (default `DEFAULT_MODEL = "gpt-4.1"`). |
| `view` | The open tab, subtab, Immerse view, both language filters and the selected entry (`saveView` / `restoreView`). |

Languages: `LANGUAGE_FLAGS` = English, French, German, Polish, Turkish. Adding a language means updating `LANGUAGE_FLAGS`, `SPEECH_LANGUAGES` and `NOUN_GENDERS`, and the keyword lists in topics.js if wanted.

## OpenAI usage

- `askOpenai(request)` calls Chat Completions **directly from the browser** with the user's key, and returns `message.content`.
- Use non-reasoning models, and always request **strict `json_schema`** output, then validate or filter the result in JS.
- OpenAI error responses have no CORS headers. A bad key therefore usually shows up as a network failure ("Couldn't get an answer…"), not as a 401.
- **Practice questions** (`makeQuestionSet` → `pickQuestionTypes` picks 5 random types in random order, max 2 per type, never the same order as `lastQuestionPlan`; A1–A2 exactly one gender; A1 no reading; failed questions are replaced once → `askForQuestions(entry, level, target, plan)` → `showQuestions`):
  - Types are listed in `QUESTION_TYPES`: reading, form, order, odd, and gender.
  - `gender` is only used at `GENDER_QUESTION_LEVELS` (A1–B2), and only for languages with genders.
  - At `WORD_HELP_LEVELS` (A1–B1), each question carries a `glossary` of new words, shown as "💡 New words".
  - Each question renders as a `.quiz-card` with a number circle. The card gets `answered-right` / `answered-wrong` once answered. `markAnswer` keeps the score.
  - Word order questions use `makeOrderQuestion`. The other types use `makeChoiceQuestion`.
- **Grammar Lens:** `findNounGenders(sentence)` → `findNounPlaces` → `drawColouredSentence`. Results are requested once per sentence (`grammarBeingFound`). `showGenderLegend(language)` fills `#gender-legend` (one `.noun` sample per gender of the language; hidden for English/Turkish). The legend is hidden in every theme (`display: none`; removed from Honey Coconut Hour at the owner's request). Honey Coconut Hour genders are solid muted fills with no outlines or underlines: Lagoon #4F6E73, Hibiscus #8A4E58, Palm #626E3D (asked for #64703F, a hair darker so #F5EADB text reaches 4.5:1), plus a faint inset top highlight rgba(255,240,220,0.08). They also apply to gender quiz answers (`.gender-option.noun`).

## Audio and speech

- **New uploads get the link:** a web link typed in Source becomes the new file's source (`fileBox` change in `makeAudioPicker`; a link auto-filled from another file is cleared instead), and `giveAudioTheLink` copies the sentence's link to a source-less file when the sentence is added or edited.
- **MP3 parts:** everything goes through `playPart(audioId, start, end, speed, handlers)` (section "Playing a part of a sound file" in app.js; `stopPart`, `changePartSpeed`). Files are decoded once with Web Audio (`decodeAudioFile`, cached in `decodedAudio`, oldest dropped above `DECODED_AUDIO_LIMIT`), because Safari seeks wrongly in VBR MP3s. 1× uses `AudioBufferSourceNode`; other speeds copy the exact part to a WAV (`makeWav`) played by `speedPlayer`, an `<audio>` element, for natural pitch. Every part plays to 0.25 s past its end (`TAIL_SECONDS`, never past the file's end) with an inaudible 10 ms fade at both ends (`CLICK_FADE_SECONDS`; GainNode at 1×, written into the WAV otherwise); saved times never change. Repeats, including text-to-speech, start after a fixed 0.7 s gap divided by the speed (`REPEAT_GAP_SECONDS`). `wakeUpAudio` must run during a tap. The native `<audio>` in the forms is only for scrubbing and Now. `playRecording(entry)` is the Immerse caller. start and end are typed in three number-only boxes, minutes : seconds : milliseconds (shown everywhere as `1:05:250`, no comma) (`makeTimeBoxes(title, seconds, readOnly)` → `{ element, get(), set(), clear() }`). Above them, read-only **Now** (live player position) and **Length** boxes in the same format; below, **Use the whole audio** (Start 0, End = file length; a hint beside it explains it and then shows the times it set) and a row of `.audio-checks` buttons (`playRange`): **▶ Play this part** plays Start→End, **▶ Check start** the first 2 s after Start, **▶ Check end** the last 2 s before End (`CHECK_SECONDS`).
- **Text-to-speech:** `speakOnce` uses `speechSynthesis`. `voiceFor` ranks the voices with `voiceQuality` (Siri, then Premium/Enhanced, and novelty voices are excluded). Setting `utterance.voice` sits in a try/catch so playback falls back to the device voice.
- Loops: `playedOnce` repeats the playback, and `stopAudio` stops it. Changing the entry stops the audio (`stopAudioIfEntryChanged`).
